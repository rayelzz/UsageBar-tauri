# UsageBar

[English](README.md) · [中文](README_CN.md) · [Русский](README_RU.md)

Компактная панель у края экрана, которая показывает расход лимитов **Codex**, **Cursor**, **Grok CLI**, **GLM**, а также подключаемых **ZCode**, **Claude**, **Copilot**, **Gemini** и **Antigravity**. UsageBar читает только локальные данные авторизации, обращается напрямую к официальным API и не передаёт ваши диалоги сторонним сервисам.

macOS 12+ · Windows · Linux · лицензия MIT · [Скачать последнюю версию](https://github.com/rayelzz/UsageBar-tauri/releases/latest)

### Возможности

- От **1 до 10** провайдеров одновременно. По умолчанию показаны Codex, Cursor, Grok CLI и GLM. В разделе **Провайдеры…** можно скрывать и переставлять элементы, не удаляя ничего из полного каталога.
- Для каждого провайдера на панели показываются до двух компактных чисел: друг над другом у левого/правого края или рядом у верхнего/нижнего. Режим **Авто** предпочитает текущую сессию или 5-часовое окно и недельный лимит. При необходимости можно вручную выбрать одно или два окна.
- При наведении показываются все окна, которые вернул провайдер: 5-часовые, недельные, месячные/расчётный период, модельные и другие, с процентами и временем сброса в системном часовом поясе.
- Codex, GLM, ZCode и Grok CLI также показывают накопленные карты сброса и срок их действия. Срок подсвечивается жёлтым, если осталось не более суток, и красным, если не более восьми часов.
- Если использованный процент неожиданно падает до **0%**, значок пульсирует зелёным и появляется уведомление. Крестик закрывает его.
- Карта сброса заранее вызывает 30-секундное уведомление: за сутки, затем за 5, 4, 3, 2 и 1 час. Один и тот же этап повторно не показывается.
- Панель можно перетаскивать и закреплять слева, справа, сверху или снизу. Карточки открываются внутрь экрана, в том числе при нижнем расположении.
- Два оформления: **Кольца использования** с тёмной подложкой и **Прозрачные значки** без неё. Доступны прозрачность и размытие; на macOS эффект следует форме панели и карточек.
- Можно показывать **использованный** или **оставшийся** лимит. Цвет всегда зависит от остатка: красный при остатке ≤ 20%, жёлтый при ≤ 40%, иначе зелёный.
- Когда курсор находится вне панели, клики проходят к окнам под ней.
- Отдельная шестерёнка открывает настройки при наведении. Правый клик закрепляет меню, крестик закрывает его.
- Автоматическая проверка обновлений по умолчанию выключена. Ручная проверка доступна в меню; найденное обновление показывает примечания к выпуску и может быть установлено с перезапуском.
- Значок приложения можно показывать в Dock, системном трее/строке меню или скрыть. Меню **UB** умеет показать/скрыть панель, обновить данные, открыть настройки и завершить приложение. При наведении на значок отображается сводка последних лимитов; та же сводка доступна в меню там, где нативное наведение не поддерживается.
- Автообновление данных раз в 60 секунд, интервал настраивается.
- Интерфейс доступен на английском, китайском и русском языках. Названия провайдеров и моделей не переводятся.

### Откуда берутся лимиты и время сброса

UsageBar ничего не оценивает по локальным логам. Приложение повторно использует уже существующую авторизацию на этом компьютере и обращается к официальному API каждого сервиса.

| Провайдер | Локальная авторизация | Официальный API | Что показывается |
| --- | --- | --- | --- |
| **Codex** | `~/.codex/auth.json` | ChatGPT `backend-api/wham/usage` и `wham/rate-limit-reset-credits` | 5 часов + неделя, дополнительные окна при наличии, карты сброса и срок действия |
| **Cursor** | Сессия Cursor в `state.vscdb`: старый `cursorAuth/userId` либо новые `glass.lastSignedInAuthId` / JWT `sub` | `cursor.com/api/usage-summary` и недельный статус Grok Bot | Месячный расчётный период: включённый объём + API, а также on-demand, командный пул и Grok Bot при наличии |
| **Grok CLI** | `~/.grok/auth.json` | `cli-chat-proxy.grok.com/v1/billing` и grok.com `GetRemainingResets` | Недельный и/или месячный лимит отдельного аккаунта Grok CLI, продукты/on-demand и карты сброса. Это не лимит Grok Bot внутри Cursor |
| **GLM** | `GLM_API_KEY`, `~/.zai/config.json` или cc-switch | Quota API `api.z.ai` либо `open.bigmodel.cn` | Все окна из `limits[]`: 5 часов, неделя, месяц, MCP и другие. Карты сброса берутся из локальной сессии ZCode либо из ответа quota |
| **ZCode** | Текущий зашифрованный ключ Coding Plan в `~/.zcode/v2/credentials.json` или старый `~/.zcode/v2/config.json`; авторизованная сессия для карт сброса | Тот же официальный quota API, что у GLM; карты — из `zcode.z.ai/api/v1/coding-plan/reset/status` | Все окна из `limits[]` и накопленные 5-часовые/недельные карты сброса при активной сессии |
| **Claude** | Связка ключей macOS `Claude Code-credentials` либо `~/.claude/.credentials.json` | Anthropic `api/oauth/usage` | 5 часов + неделя + отдельные недельные окна моделей, дополнительное месячное использование при наличии |
| **Copilot** | `~/.config/github-copilot/apps.json` / `hosts.json`, авторизованный GitHub CLI, включая системное хранилище ключей, либо `GITHUB_TOKEN` | GitHub `copilot_internal/user` | Ограниченные месячные категории, обычно Premium, и дата сброса |
| **Gemini** | Gemini CLI `~/.gemini/oauth_creds.json`; в Windows — также авторизованная сессия Gemini Desktop | Cloud Code Assist `retrieveUserQuota` либо запрос лимитов Gemini Web | По возможности модельные квоты CLI/Code Assist, иначе 5-часовой и недельный лимиты пользовательского плана Google AI. Cookies расшифровываются только в памяти и отправляются только Google. Защищённый DPAPI локальный кэш сохраняет доступ к данным, пока Gemini Desktop блокирует свою cookie-базу |
| **Antigravity** | `~/.gemini/antigravity-cli/antigravity-oauth-token` | Cloud Code Assist `fetchAvailableModels` | Остаток и время сброса для каждой модели |

Файл сессии Cursor:

- macOS: `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb`
- Windows: `%APPDATA%\Cursor\User\globalStorage\state.vscdb`
- Linux: `~/.config/Cursor/User/globalStorage/state.vscdb`

Проценты и время сброса берутся непосредственно из ответа API. Время отображается календарной датой и в 24-часовом формате системного часового пояса. Истекающие токены по возможности обновляются локально. Если сервис не установлен или пользователь не авторизован, UsageBar показывает «Нет данных».

### Установка

Для каждого выбранного сервиса нужна рабочая авторизация **на том же компьютере**. Установщик не содержит чьих-либо аккаунтов или токенов.

1. Скачайте пакет для своей системы из раздела [Releases](https://github.com/rayelzz/UsageBar-tauri/releases/latest):
   - macOS Apple Silicon: `aarch64.dmg`
   - macOS Intel: `x64.dmg`
   - Windows: `x64-setup.exe`
   - Linux: `.AppImage` или `.deb`
   - В Windows setup открывает выбор языка и полноценный мастер установки. На странице параметров выберите автозапуск вместе с Windows. На последнем шаге отдельно доступны ярлык на рабочем столе и немедленный запуск — обе галочки по умолчанию сняты. Позже автозапуск меняется пунктом **Запускать при входе** в настройках UsageBar.
2. Сборки macOS подписаны ad-hoc и не нотарифицированы Apple. После копирования `UsageBar.app` в **Applications** один раз выполните в Terminal:

   ```bash
   xattr -cr /Applications/UsageBar.app
   open /Applications/UsageBar.app
   ```

   Сообщение «UsageBar.app повреждено» обычно означает карантин Gatekeeper, а не повреждённый файл.
3. Войдите в нужные официальные приложения или CLI: Codex, Cursor, Grok CLI, GLM/z.ai, ZCode, Claude Code, GitHub Copilot, Gemini CLI или Gemini Desktop, Antigravity. Затем выберите их в **Провайдеры…**.

Сборка из исходников:

```bash
npm install
npm run tauri dev      # режим разработки
npm run tauri build -- --no-sign  # неподписанный локальный установщик
```

Готовые файлы находятся в:

- macOS: `src-tauri/target/release/bundle/dmg`
- Windows: `src-tauri/target/release/bundle/nsis` и `msi`
- Linux: `src-tauri/target/release/bundle/appimage` или `deb`

Pull request запускает JavaScript- и Rust-тесты, затем собирает неподписанные пакеты Windows x64, Linux x64, macOS Apple Silicon и macOS Intel по сценарию `.github/workflows/ci.yml`.

Тег вида `v*` запускает release workflow и публикацию пакетов для macOS, Windows и Linux. Локальная сборка не создаёт тег или GitHub Release.

### Настройки

Наведите курсор на шестерёнку или нажмите правой кнопкой по панели:

- обновить данные сейчас; автообновление от 15 секунд до 10 минут либо выключено;
- зафиксировать положение и включить/выключить пропуск кликов;
- закрепить панель слева, справа, сверху или снизу;
- выбрать оформление, использованный/оставшийся лимит, прозрачность и размытие;
- выбрать язык: English, 中文 или Русский;
- в **Провайдеры…** выбрать 1–10 провайдеров и изменить их порядок; внутри каждого оставить **Авто** или выбрать до двух конкретных окон. Скрытие убирает только элемент с панели — провайдер остаётся в каталоге;
- выбрать, где показывать значок приложения: Dock, системный трей/строка меню или нигде;
- проверить обновление, включить автопроверку, запуск при входе и выйти из приложения.

Все настройки — край экрана, координаты, провайдеры и их порядок, выбранные окна, оформление, режим процентов, прозрачность, размытие, значок, язык, интервал, блокировка, пропуск кликов и обновления — хранятся в `~/.usagebar/prefs.json` и сохраняются после перезапуска или обновления.

### Вопросы и ответы

**Почему у провайдера написано «Нет данных»?**

Сервис не авторизован на этом компьютере либо UsageBar не может прочитать его локальные учётные данные. Войдите через официальное приложение/CLI и нажмите **Обновить сейчас**.

**Cursor сообщает, что авторизация не найдена.**

UsageBar читает `cursorAuth/accessToken` из локального `state.vscdb`, затем ищет идентификатор в `cursorAuth/userId`, `glass.lastSignedInAuthId`, `adminSettings.cachedAuthId` или поле `sub` JWT. Откройте Cursor Desktop на этом компьютере и войдите в аккаунт.

**Grok показывает «Нет данных», хотя вход выполнен.**

Сессия Grok CLI хранится в `~/.grok/auth.json`. UsageBar поддерживает новые ответы unified billing без `creditUsagePercent`, читает месячные/on-demand поля и сохраняет недельное окно даже при отсутствующем проценте.

**Почему Grok есть и отдельно, и внутри Cursor?**

**Grok CLI** — самостоятельный аккаунт и его биллинг. **Grok Bot · Weekly limit** — отдельный лимит, который Cursor возвращает как часть своего плана. UsageBar не объединяет эти значения.

**Почему после передачи приложения другому человеку не видны мои Cursor/Codex?**

Так и задумано: авторизация остаётся только на исходном компьютере. Каждый пользователь входит в собственные сервисы самостоятельно.

**Claude, Copilot, Gemini или Antigravity не показывает данные.**

Сначала войдите в официальный CLI или приложение на этом компьютере. Claude читает связку ключей или `~/.claude/.credentials.json`; Copilot — локальные файлы GitHub Copilot, GitHub CLI/keychain либо `GITHUB_TOKEN`; Gemini — OAuth Gemini CLI, а в Windows также сессию Gemini Desktop; Antigravity — собственный OAuth-файл. UsageBar не вычисляет расход по журналам.

**Gemini Desktop запущен, но его cookie-база заблокирована.**

Это штатное поведение приложения Gemini в Windows. Когда база доступна, UsageBar сохраняет только необходимую сессию в локальном файле, защищённом Windows DPAPI. После этого 5-часовой и недельный лимиты продолжают обновляться и при запущенном Gemini Desktop. Если Gemini ни разу не определился, закройте его один раз, нажмите **Обновить сейчас**, затем снова запустите.

**Загружает ли UsageBar диалоги или помещает токены в установщик?**

Нет. Приложение читает локальную авторизацию и запрашивает только официальные usage API. Диалоги не читаются, учётные данные не включаются в сборку.

**Не получается нажать на окно за панелью.**

Включите **Не блокировать клики под панелью**. Когда указатель находится вне активной области, клики проходят насквозь.

**Не получается нажать на панель или открыть меню.**

При включённом пропуске кликов прозрачная область вокруг значков тоже может пропускать нажатия. Наведите курсор непосредственно на кольцо или шестерёнку. Также можно отключить пропуск кликов и зафиксировать положение.

**macOS пишет, что UsageBar повреждено или разработчик не определён.**

Скопируйте приложение в `/Applications` и выполните:

```bash
xattr -cr /Applications/UsageBar.app
open /Applications/UsageBar.app
```

**Что означают цвета?**

Зелёный: использовано менее 60%. Жёлтый: 60–80%. Красный: 80% и больше.

**Как указать ключ GLM/z.ai?**

Экспортируйте `GLM_API_KEY`, `ZAI_API_KEY` или `Z_AI_API_KEY`, используйте `~/.zai/config.json` либо настройте GLM/智谱/z.ai в cc-switch.

**ZCode и GLM показывают одно и то же?**

Не обязательно. ZCode — coding agent, GLM — модель/API. ZCode читает сохранённый ключ Coding Plan из `~/.zcode/v2/credentials.json` или старой конфигурации; GLM читает shell, `.zai` или cc-switch, с локальной сессией ZCode как резервным источником. Значения совпадут только для одного и того же плана. Карты сброса требуют активной сессии ZCode; UsageBar расшифровывает локальные `enc:v1:` только в памяти и не активирует карты.

**Особенности Windows и Linux.**

В Windows требуется WebView2; установщик умеет загрузить его. Значок в трее появляется только при соответствующей настройке. В Linux нужен рабочий системный трей; если нативное наведение недоступно, сводка лимитов остаётся в tooltip и меню значка.

### Конфиденциальность

- Учётные данные остаются на вашем компьютере.
- Запросы отправляются только официальным API провайдеров.
- Содержимое диалогов не загружается.
- Сторонней телеметрии нет.
